# v0.7 CRUNCH LINE — 研究記録（総監督）

人間の評価は [PLAYTEST_CRUNCH.md](../PLAYTEST_CRUNCH.md)（未検証）。数値の元データ：`research/v07/compare.json`（`node tests/crunch/compare.mjs`）、`input.json`、`perf.json`。

## 1. 技術の選択
| 決めたこと | 理由 |
|---|---|
| v0.6（`research/v0.6-sound`）から `research/v0.7-crunch` を作り、別ページ `crunch.html` にした | v0.6 の `stages.html`、v0.5 の `feel.html` を比較用に残すため |
| 一撃ごとの変化は「本当に切り落とす」にした（`crunch/crunch.js` の `K.hurt`） | HP の棒ではなく、形・断面・亀裂で破壊の過程を見せるため。v0.3 の切断エンジンをそのまま使い、大きい方のかけらを敵として残す |
| 切り落としは「撃破」として数えない | 切断の仕組み（`fracture`）は深さ0の体だけを撃破として報告する。切る瞬間だけ深さを0.5にし、残った本体は深さ0に戻す |
| 操作（`feel/heroes.js`）には、使わなければ何もしない口を1つだけ足した（`C.onPunch`） | 拳闘士の「倒しきれない一撃は削って押し返す」に必要。v0.5・v0.6 では未設定なので挙動は同じ |
| 明るい背景は、描画エンジンを変えずに「一番奥に背景の絵を描く」で作った | v0.3 のエンジン（`lab/gl.js`）は暗い色で画面を消す。共有のエンジンを変えないため |
| 斜め70°の 2.5D カメラは作らず、床の線を上の一点へ狭めて奥行きを出した | 依頼どおり「操作座標の一致を優先、低コストに」。透視をかけると、指と攻撃の位置がずれる |
| 「少数戦は大きく、無双では広く」は、カメラのズームではなく敵の大きさで表した | 同じ理由（座標が一致したまま）。開幕は半径80〜90、大群は27〜32 |
| 有料サービス・Codex は使っていない | 依頼どおり |

## 2. 失敗と直し方
| 何が起きたか | 原因 | 直し方 |
|---|---|---|
| 大群の出現でページが止まった | 出す隊形を選ぶとき、`find` の中で毎回乱数を引き、どれにも一致しないことがあった | 先に隊形を1つ決めてから探す |
| 背景が出ず「ファイルが見つからない」 | 素材の読み込みは画像の URL を期待していたが、描画用の部品（canvas）を渡していた | 画像データ（data URL）にして渡す |
| 拳闘士だけ、最初の撃破が13秒後、侵入4回 | とどめで殴り飛ばした敵が画面の上端で跳ね返り、そのまま落ちてラインを越えていた（v0.5 は上に群れがいて止まっていた） | 後ろに群れがいれば殴り飛ばす（v0.5 の玉突き）、いなければその場で砕いて破片を飛ばす。下向きに転じた飛行中の敵は、その場で砕ける |
| 殴り飛ばした敵が、飛び終わっても壊れずに残る | 飛行時間が切れると物理の側で先に「飛行中」が解け、最後の破壊の判定が飛ばされる | 着地した時点で、とどめ済みなら砕き、押し返しただけなら行進に戻す |
| 削った切り口が「絵をまっすぐ切っただけ」に見え、中身は0.8秒で消える | 断面の演出（本が開く）は切った瞬間だけ | 残った本体の切り口に、素材の中身の色の帯を描き続ける。亀裂は切り口から内側へ伸ばす |
| 防衛の緊張感がゼロ（ラインの近くに敵がいる時間 0%） | 敵が遅く、ボットが先に倒してしまう | 群れ 46→62、大群 58→84、硬い新型 24→32 px/秒に上げ、大群を密集させた。それでも人間らしいボットではほぼ0%（§4） |
| 人間に近いテンポだと、ボスを倒しきれない | ボスの時間が12秒しかない | ボスを42秒→40秒に早め、硬さを 外殻6/中層4/核16 → 5/3/12 にした |
| 上の情報欄が2行に折り返す | 侵入の表示を足して幅が足りない | 1行に詰めた |

## 3. ボット
| ボット | 狙い方 | 用途 |
|---|---|---|
| 人間らしい（intent） | 0.4秒ごと。ラインの手前250px以内に敵がいれば一番下の敵、いなければ群れの濃い所 | 主な比較 |
| のんびり（casual） | 人間らしいと同じ狙い方で、0.75〜1.05秒ごと、狙いに±30pxのぶれ | 人間に近いテンポの代わり |
| 群れだけ（dense） | v0.5 の人間らしいプレイヤー。ラインを見ず、群れの濃い所だけ | 「下の敵を優先する」ことの効き目を見る |
| でたらめ（random） | 画面のどこかを適当に触る | 下限 |

## 4. v0.6 と比べて（4戦場 × 3キャラ、`tests/crunch/compare.mjs`）
v0.6 は Stage 1（ロウだけ）と Stage 3（混成）。

| 確かめたいこと | 指標 | v0.6 | v0.7 |
|---|---|---|---|
| 開幕の一体を壊す過程が見えるか | 開幕12秒の画面上の敵の数 | 12〜30体 | 1.2〜1.6体（のんびり：2.5〜3.4体） |
| | 一体を壊すのに必要な打数 | 1.0 | 2.9〜3.0 |
| | 削れた状態で残る時間 | 0秒（一撃で壊れる） | 0.8〜1.4秒（のんびり：2.0〜3.1秒） |
| 強化後、同じ敵が弱く感じるか | 最初の敵の打数 強化0 → 1 → 2回 | — | 3.0 → 1.0〜1.6 → 1.0（1回目の強化後に1を超えるのは、強化前に削られていた敵が残るため） |
| 硬い新型で、また何度も叩くか | 硬い新型の打数（強化2回後） | — | 3.0 |
| 大量撃破の爽快感 | 大群の時間の一手あたりの撃破（人間らしい） | 大剣士 21〜23 ／ 拳闘士 17〜18 ／ 魔法使い 35〜36 | 大剣士 **26.7** ／ 拳闘士 **11.9** ／ 魔法使い **22.9** |
| | 大群の時間の一手の最大 | 53 ／ 47〜52 ／ 55〜57 | 49 ／ 38 ／ 47 |
| 侵入の緊張感 | 侵入（1プレイ平均） | （ラインなし） | 人間らしい・のんびり：0。群れだけ・でたらめ：拳闘士で 0.5 |
| | ラインの手前250pxに敵がいる時間 | （参考：画面下部に敵がいる時間 13〜71%） | 0〜1.7%（のんびり拳闘士だけ 9.2%） |
| ボス | 撃破（人間らしい） | 4/4（4.9〜10.5秒） | 4/4（大剣士 5.3、拳闘士 10.5、魔法使い 7.5秒） |
| | 撃破（のんびり） | — | 大剣士 4/4（13.0秒）、拳闘士 **0/4**、魔法使い 2/4（14.2秒） |

読み取り：
- 「一つを味わう」は数字の上ではできている。開幕の敵は1〜3体で、3回叩いて壊れ、削れた姿が1〜3秒見える。強化1回で一撃になる。
- 大群の爽快感は、大剣士は v0.6 より上がった。しかし**拳闘士と魔法使いは、一手あたりが v0.6 の6〜7割に下がった**。v0.6 は画面中央に密集した群れを一度に叩けたのに対し、v0.7 の大群は上から流れてくるので、一度に巻き込める数が少ない。
- **防衛の緊張感は、ほとんど生まれていない**（侵入0、ラインの近くに敵がいる時間もほぼ0%）。「忙しすぎない」は満たしているが、緊張感が足りない可能性がある。人間はボットより遅いので、実際には敵がもっと近づくはず（未検証）。
- 人間に近いテンポだと、拳闘士はボスを倒しきれなかった（0/4）。

## 5. 実際のタッチ操作（Chrome、スマホの画面サイズ、`tests/crunch/input.mjs`）
- 上（y=330）とラインの近く（y=930）に1体ずつ置き、近い方を触った。3キャラとも、近い敵だけが削れ（面積が 13〜42% 減り、亀裂2〜3本）、上の敵には当たらなかった。
- 拳闘士の一撃で、敵は 60px 押し返された。
- 強化の画面は時間を止め、「威力 1 → 3：最初の敵が一撃で壊れる」を表示し、選んだ強化が反映された。エラーなし。

## 7. 人間が確かめるまで分からないこと（未検証）
依頼書の7つの問いすべて（評価シート参照）。とくに：
- 削れ・亀裂・中身の帯が、スマホの画面の大きさで「壊れていく過程」として見えるか。
- 緊張感が足りないのか、ちょうどよいのか。
- 明るい画面での見やすさ（破片や攻撃の軌跡の色）。

## 8. 次の仮説
1. 緊張感：大群の後半で敵の速さを少しずつ上げる、または硬い新型をラインの近くまで来やすくする。
2. 大群の爽快感（拳闘士・魔法使い）：大群を「画面中ほどで一度止まる密集隊形」にして、まとめて叩ける瞬間を作る。
3. 拳闘士のボス：一撃でボスに与える手応えを増やす（v0.5 では3回分）か、ボスの時間を延ばす。
4. v0.6 の「1ステージ1素材」と組み合わせる：開幕の大きな敵を、そのステージの新素材にする。
