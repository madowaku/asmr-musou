## エンジンの接続点

`lab.html` は classic scripts、名前空間は `window.LAB`。720×1280論理座標。Canvas2Dは手続きテクスチャ生成だけに使用する（テストの画像合成は別ページ）。HUDはHTML。描画のglowは加算、ゼリーの断面の屈折は色のずれによる近似で、背後の実像を屈折させる光学シミュレーションではない。

### 純粋幾何

`require('./lab/slice.js')` と `LAB.slice` は同じAPI。

- `splitLine(poly, a, b, options)` は無限直線、`splitPath(poly, points, options)` は実際の有限軌跡。
- `splitBody({poly, depth}, points, {maxDepth:3, minArea, cutId})` は深さ制約つき。
- 結果は `{pieces, debris, sourceArea, cut}`。元の引数は変更しない。
- 各頂点は `{x,y,u,v,cut}`。`cut` はその頂点から次の頂点へ向かう**辺**のID。切断しても古い断面IDを保持する。
- `triangulate(poly)` は添字配列。`area`、`centroid`、`contains`、`resample` も公開。
- 穴のない単純多角形が入力。物体の中だけに閉じた穴をくり抜く操作は未対応。グラフの面積照合で元の物体を保持する。自己交差する入力輪郭は未対応。

### 素材・イベント

`LAB.registerMaterial({id, name, hardness, layers:{shell,core}, crossSection, init(body,parent), onCut(body,cut), onImpact(body,impact), onPress(body,localPoint), update(dt,body), draw(renderer,body)})`。必須フィールドは登録時に検査。`init` / `draw` は今回のランタイム補助。

`onCut` は元のbodyと、生成済みの `children`、ワールド座標の `faces`、`speed`、`length`、`area`、位置などを受け取る。速度はlogical px/s、長さはpx、面積はpx²、時間は秒。`LAB.events.on(name, handler)` はunsubscribe関数を返す。`cut` / `crack_grow` / `peel` / `wobble` が音声接続点。イベントにはmaterial、x/y、speed、length、area、frame、simulation timeを付ける。`crack_grow.growthRate` はpx/s、`wobble.frequency` は目標周波数Hz、`amplitude` は断面変位RMSのpx。実際の固有周波数は形状でも変わる。

通常の音は `lab/audio.js` の小さい仮実装。音声担当はこれを置き換えて同じイベントを購読できる。既存の並行制作 `lab/audio/` はここでは読み込まない。現在の操作側は `LAB.audio.unlock()` / `toggle()` を呼ぶので、本格音声の `init()` / `setEnabled()` とは統合時に合わせる。

### 画像・粒子・調整

`LAB.tex('wax_body')` / `jelly_body` / `wax_core`。`LAB.textureNames` でスロットからバンドルキーへの別名を指定できる。`npm run bundle:lab` は全PNGを `lab/assets-bundle.js` に埋め込むだけで、元アセットを変更しない。キーは `/` 区切りの相対パス、拡張子なし。R0-Aでコミットするファイルは空のバンドルで、アート担当の制作途中のPNGを固定しない。PNGを使う際には輪郭、余白、UVを合わせる必要がある。今回の画像はすべて手続きテクスチャ。

`LAB.addParticle` は位置、速度、size、color、kind（0 chip / 1 drop / 2 grain / 3 cube）、寿命などを受ける。WebGL側のインスタンスバッファは必要量に拡大する。ランタイムは既定1200粒で古い粒を退ける。`LAB.config` に深さ3、微小面積8、body上限240、粒上限1200、重力250をまとめた。テスト時は補充のたびに120片へ整理し、その後の切断で増える（最終測定では最大162片）。

## 測定の範囲と残る課題

性能は10秒間、実マウスを連続移動し、0.45秒ごとに40体を補充する。切断入力はキューでrAF内へ移し、切断、補充、軟体更新、粒子、描画命令のJS時間をすべて計る。GPU完了・コンポジター・ポインターdispatch・実機の入力遅延は含まない。平均/p95だけでなく最大も記録。4倍CPU制限はAndroid実機の代用ではない。メモリ、熱、長時間運転、人間の気持ちよさ・快適さは未評価。

- **wax：部分的に成立。** 指どおりに斬れ、薄い殻と明るい芯の差、走る亀裂、セルごとの剥離が読める。手続きの外面はまだ滑らかな飴にも見える。薄い殻の反りと粉っぽい芯の触覚、素材音は追加研究が必要。剥離途中で切ると、完全露出前のセルごとの損傷履歴は子片へ継承されず、新しい殻の見た目に戻る。この履歴のUV空間での保持は残課題。
- **jelly：切断面のぷるぷるは成立。** 静止画でも断面中央の弓なりと戻りが見える。輪郭・内部の頂点が実際に移動し、約0.6–1.0秒の余韻がある。ただし2Dの弾性表現で、体積保存、自己衝突、真の透過屈折はない。細長い再切断片やもっと大きな外力には追加検証が必要。
- 群れは最小限の測定用配置。素材同士の衝突・破片から敵へ伝わる連鎖は実装していない。床は簡易反発。無双本編への採用には自然な分布、wave、敵の動き、素材同士の連鎖上限が必要。
- 石鹸には占有グリッドと、切断後に外へ伝わる崩落時間場。砂にはアルファからの粒生成、3000粒級の予算、堆積/静止。どちらも今回のinstancingとeventsを再利用できるが、合成負荷を再測定する必要がある。
- スポンジ/粒入りスライムには押し込み・流量・内部粒の所属保持、琥珀糖には硬い殻と軟体コアの一体管理、チョークには粉と粒度別の寿命が必要。アート統合には正式な輪郭/UVメタデータが必要。
