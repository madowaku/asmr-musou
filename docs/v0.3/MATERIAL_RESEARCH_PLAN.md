# v0.3 研究計画：素材そのものを斬る・砕く・崩す（無双への回帰）

作成：2026-11-22／総監督（Claude）。状態：**計画のみ**。v0.2（PR #1）を人間が試遊して納得してから着手する。

## 1. 方向転換の整理
v0.2 は「1体ずつ丁寧に味わう癒やし系タップ」に寄った。原点は **ASMR素材の敵をバッサバッサ倒す無双**。v0.3 では軸を次のように置き直す。

| 軸 | v0.2 | v0.3 で目指すもの |
|---|---|---|
| 主操作 | タップ（なぞりは補助） | **なぞり＝斬撃が主役**。タップと長押しは硬い敵向けの補助 |
| 倒し方 | HP段階で状態が切り替わる | **軌跡の角度どおりに実際に分断される**。素材ごとに壊れ方が違う |
| 量 | 同時に最大12体 | **一振りで20体前後**を巻き込める群れ |
| 連鎖 | プチプチの距離連鎖だけ | **破片が他の敵に当たって壊れる**物理連鎖 |
| 音 | 1体＝1音 | 斬撃の速さ・素材・撃破数で鳴り方が変わる（群れを1つの音のうねりに束ねる） |

v0.2 の資産（破断フレームの集約、ヒットストップ、音の帯域ゲート、試験の仕組み）はそのまま土台にする。

## 2. 研究対象の4素材と技術方針

### 2.1 ロウ破壊：細かい亀裂が走り、殻が剥がれ落ちる
- 亀裂：衝撃点から**ボロノイ分割**で殻のセルを作る。亀裂は 60〜120ms かけて**伸びていくアニメーション**（セル境界を距離順に描画）。
- 剥離：セルごとに遅延（距離 × 乱数）をつけて剥がし、殻チップのスプライトとして回転しながら落とす。下からクリーム色の芯が現れる（v0.2 の wax_2_alt の文法を継承）。
- 斬撃との関係：斬られた面に沿って殻が一気にめくれる。
- 音：亀裂の伸長に同期した細かいパチパチ（粒の密度 ∝ 亀裂の伸長速度）と、剥離ごとの小さなカリッ。

### 2.2 ゼリー切断：切断面がぷるぷる震える
- 本体を**ばね質点の輪郭（ソフトボディ）**として持つ。斬撃線で輪郭ポリゴンを2つに分け、それぞれ新しいソフトボディにする。
- 切断面の頂点に強めのばね振動を与え、**切断面だけがぷるぷる震える**ようにする。断面は半透明のグラデーションにハイライト線（つやのある断面）を重ねる。
- 描画：輪郭に沿ってスプライトをクリップする。変形が大きい場合は三角メッシュでテクスチャを貼る（Canvas の三角形ごとのアフィン変換、または WebGL）。
- 音：切れる瞬間のぷちゅっ＋断面の揺れ周期に合わせた小さな水音。

### 2.3 石鹸ゴーレム：斬った場所から細かい立方体が崩れる
- 体を**2Dの立方体グリッド（ボクセル）**で構成する。見た目は生成スプライトで、内部では各セルの占有状態を持つ。
- 斬撃線の近くのセルから順に**立方体パーティクル**として剥がれ、崩落が外側へ伝わっていく（200〜400ms）。立方体は3面の陰影を持つスプライトで、転がって床に積もる。
- 試作画像：`concept_soap_golem_luna.png`（gpt-6-luna 経由の内蔵 image_gen で生成。泡付き・手足あり。採用するかは未定）。
- 音：ショリッという切削音＋立方体同士が当たるコトコトという小さな打音（数が多いので束ねて合成する）。

### 2.4 砂の巨人：一刀両断するとサラサラ崩れていく
- 斬られた瞬間に、体を**数千粒の砂パーティクル**に変換する（スプライトのアルファから粒の位置と色をサンプリング）。
- 斬撃線から外側へ「崩壊フィールド」が時間差で広がり、粒は重力で落ちて下に山を作り、消えていく。
- 1粒ずつの描画は Canvas 2D では重いため、**WebGL のポイントスプライト**が必要になる可能性が高い（下の判断ゲートを参照）。
- 音：長いサラサラ（帯域を絞ったノイズの粒状合成。粒の流量に音量を連動）と、最初のザンッ。

## 3. 共通の技術基盤
1. **輪郭の取得**：各スプライトのアルファからマーチングスクエアで輪郭を抽出し、単純化した凹多角形として持つ（事前計算してJSONで保存）。
2. **斬撃による分割**：軌跡の線分（直近の数点を直線近似）で多角形を分割する。凹多角形の分割は線とポリゴンのクリップで行い、各片には切断線の法線方向の速度と回転を与える。片はもう一度斬れる（深さ上限は2〜3）。
3. **切断面のシェーディング**：分割辺に沿って素材ごとの断面を描く（ロウ＝殻の縁＋クリーム色の芯、ゼリー＝つやのある半透明、石鹸＝白い立方体の目、砂＝ざらついた粒）。
4. **破片の物理と連鎖**：破片を剛体（円か凸包）として扱い、敵と衝突させる。相対速度が閾値を超えたら衝突相手を壊し、そこから連鎖が広がる。全体の上限を設けて、終わりのない連鎖は止める。
5. **群れ**：小型の雑魚（半径 25〜35）を30〜40体出し、大型と混ぜる。一振りで20体を巻き込める密度と軌跡判定にする。
6. **音の束ね方**：同じフレームで N 体が壊れたら N 個の音を鳴らさず、「群れ用」の音1つ（密度と長さが N に比例）と、最初と最後の数体の個別音で表現する。v0.2 の帯域ゲート（電力の50%以上が500Hz〜8kHz、最大トランジェントは8ms以内）は維持する。

## 4. 判断ゲート（Canvas 2D のままか、WebGL に移るか。Blender を使うか）
- **ゲートA（研究1の終わり）**：中位Androidの近似として CPU を4倍スロットルし、「ゼリー20体を同時に斬る」で p95 が 8ms 未満なら Canvas 2D を続行する。超えたら WebGL2 の描画層（ライブラリなし、または最小限）へ移行する。
- **ゲートB（研究2の終わり）**：砂3,000粒＋立方体300個で p95 が 8ms 未満か。満たせなければ WebGL のポイントスプライトに切り替える。
- **Blender の採否**：2Dの切断で「立体の断面」がどうしても嘘っぽく見える場合に限り、Blender で**断面テクスチャ**や**事前レンダリングした破砕シーケンス**（ボス用）を作る。その場合は Blender 本体と MCP サーバーの導入が必要（現在は未インストール）。導入するのはゲートAの結果を見てから。

## 5. 研究の進め方（各段階の完了条件つき）
| 段階 | 内容 | 完了条件 |
|---|---|---|
| 研究0 | `lab.html`：1体ずつ素材を切り替えて斬れる実験場。fps表示、スロー再生、33msのコマ送り | ブラウザで開くと動く。スクリーンショット撮影がテストに入っている |
