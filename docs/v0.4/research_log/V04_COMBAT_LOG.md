## 1. 技術選定
| 判断 | 理由 | 判定 |
|---|---|---|
| v0.3 の研究所の部品（斬撃、WebGL2 描画、8素材、断面、音響）をそのまま読み込み、戦闘用の土台 `combat/world.js` を新しく書く | 素材の壊れ方の資産を使い切る。研究所の `main.js` には手を入れない（研究所を守る） | 採用 |
| 横から見た画面（浮かぶ素材の群れ、切れた片は重力で落ちる） | v0.3 の正面スプライトと物理をそのまま使える。真上からの視点にすると、破片の落下と断面の見せ方を作り直す必要がある | 採用 |
| キャラクターの絵はプログラムで描く | Codex（画像生成）が利用上限のため。役割が読める最小限のシルエットにした | 暫定（画像生成が使えるようになったら差し替える） |
| 同じ乱数シードで決まった結果になる、描画なしの模擬 `COMBAT.test.simulate` | AI による客観検証を、60秒の試合1回あたり約0.1〜0.3秒で回せる。キャラ間を同じ条件で比べられる | 採用 |
| 1フレームで処理する撃破は4体までにし、残りは次のフレームへ回す | 重いフレームをなくす。同時に、撃破が時間差で連なって「破断の波」になる | 採用 |
| 戦闘画面では、片の断面（本のように開く表現）を0.45〜0.8秒で閉じる | 片が多いと、すべての断面を描くのが一番重かった。見せたいのは切った瞬間だけ。研究所の共有コードは変えず、戦闘側で上書きした | 採用 |

## 2. 操作の研究
- 採用：**キャラクターを基準にした相対操作**。親指を画面のどこに置いても、なぞった形のままキャラが動く（剣士は1.5倍、拳闘士は1.65倍、魔法使いは1.2倍に拡大）。攻撃は「キャラの体が通った所が壊れる」ので、敵を直接消しているようには見えない。
- 採用：長押し（170ms 静止）→ 引いて離す ＝ スリングショット。照準線（剣士・拳闘士）と重力球の範囲（魔法使い）を、離す前に見せる。
- 採用：タップ ＝ その場の小技（回転斬り／地面打ち／近い敵への雷）。狙う対象は自動で選ぶ（補助）。
- 検証：実際のポインター操作で、3キャラすべての3入力が意図どおりの技になることを自動テストで確認した（`tests/combat/input.mjs`）。なぞった向きの誤差は1°以内。

## 3. 失敗と、その直し方（記録）
| 失敗・問題 | 原因 | 対処 |
|---|---|---|
| ボスが開始5.7秒で出る | 上手いプレイヤーは陣形5つを約1秒ずつで片づける | ラッシュを約30秒に固定し、陣形は一巡ごとに配置と速さを変えて繰り返す。上手いほど多くの陣形と戦える（＝撃破数が増える報酬） |
| 2回目以降の試合で、次の陣形が出ない | 試合開始時に `L.time` を戻していなかった（陣形の経過時間がずっとマイナスのまま） | 試合開始時に、時刻・ID・乱数をすべて初期化する。人間が「もう一回」を押したときにも起きていたバグ |
| 剣士がボスの外殻を3枚切ったところで止まる | まだ壊せない内側の層に刃が当たって弾かれていた | 鍵のかかった層は、当たり判定そのものから外す（外殻の奥にあるので、刃や拳は素通りする） |
| 拳闘士がボスの核を殴り飛ばして、画面外へ消す | ボスの部品も弾として飛んでいた | ボスの部品は飛ばさない。代わりに勢いのある破片を散らし、隣の板へ連鎖させる（拳闘士らしいボスの壊し方） |
| 魔法使いがボスを倒せない | 風（移動）にマナを払っていたので、重力球の4マナがたまらない | 風はマナ消費なしにする。マナは雷（2）と重力球（4）だけで使う |
| 選択画面などが常に表示される | CSS の `display:flex` が `hidden` 属性を上書きしていた | `[hidden]{display:none!important}` |
| 後回しにした撃破で例外が出る | 処理上限で後回しにした処理が、実行時の弾の状態を読んでいた | 弾のエネルギーなどの値は、後回しにする時点で確定させる |
| 時間切れの崩落が「一手の最大」に混ざる | 崩落も一手として数えていた | 崩落は自分の一手としては数えない（`system` 扱い） |

### 依頼書の検証観点への、AI 側の答え
| 観点 | AI の客観検証で分かったこと | 人間の評価が必要な部分 |
|---|---|---|
| 意図した攻撃を出せるか | 実際のポインター操作で、3キャラ × 3入力すべてが意図どおりの技になる | 指でのなぞりやすさ、長押しの判定時間（170ms）が自然か |
| キャラごとに戦い方が違うか | 連鎖撃破は拳闘士だけが多い（246体）。得意な陣形がキャラごとに違う。一手の最大も「剣士＝安定」「拳闘士＝連鎖で跳ねる」「魔法使い＝仕込みが決まると大きい」と性格が分かれた | 体感として「別のゲーム」に感じるか |
| 敵の配置を読む意味があるか | 陣形によって必要な手数がキャラごとに変わる（例：縦列は拳闘士1.9手、魔法使い6.7手） | プレイ中に陣形を読もうと思えるか（ヒント表示が役立つか） |
| 連鎖を予測して狙えるか | 拳闘士は、狙う（上手い）と連鎖撃破が 81 → 246 体に増える。でたらめでも連鎖は起きる | 弾の行き先が読めるか（予測線は溜めパンチにだけある） |
| 大量撃破が単体撃破より気持ちいいか | 構造上、撃破数に応じて音の質感が段階的に変わる（v0.3 の破断の波）。「KO」表示も数に応じて大きくなる | **ここは人間にしか評価できない** |
| 単調な作業になっていないか | 上手いボットでも陣形ごとに手が変わる。ただし剣士は全陣形を約2手でこなすので、単調になる可能性がある | 何回目で飽きるか |
| もう一度遊びたくなる仕掛けがあるか | 結果画面ですぐ再挑戦できる。同じ戦場でキャラを切り替えられ、比較表が出る。キャラ別の自己ベストに NEW 表示が出る | 実際に「もう一回」を押すか |

## 6. 総監督の所見と、次の仮説
- 剣士が最も強く、最も簡単（上手いボットで一手あたり8体）。「適当でも気持ちいい」の入口として残すか、拳闘士・魔法使いとの差を縮めるかは、人間の評価で決める。
- 魔法使いの「素朴」（雷を撃ちまくる）はボスを倒せない。マナをためる判断が要る＝「少し考えると気持ちいい」が数字に出ている。ただし、人間にとって厳しすぎないかは要確認。
- 時間切れでも、ボスは自分から崩れて余韻まで見せる（罰がない）。
- 次の候補：連鎖が起きたときのスロー演出、拳闘士の弾の予測線（通常パンチにも）、陣形ごとの「上手い解き方」をリプレイで見せる、キャラ画像の生成。
