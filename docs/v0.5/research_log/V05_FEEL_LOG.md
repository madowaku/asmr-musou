設計：[FEEL_DESIGN.md](../FEEL_DESIGN.md)。数値の全表：[research/v05/summary.md](../../../research/v05/summary.md)（`node tests/feel/summary.mjs` で再生成）。

**読み方**：この記録の数値はすべて **AI による客観検証**（自動プレイヤーと自動テスト）。気持ちよさは測っていない。人間の主観が必要な項目は §6 に「未検証」としてまとめた。

## 1. 技術選定
| 判断 | 理由 | 判定 |
|---|---|---|
| 新しいページ `feel.html` と `feel/`（heroes / game / sfx / css）。v0.4 の `combat.html` はそのまま残す | 操作の前後比較を、同じビルド・同じ素材エンジンで行うため | 採用 |
| v0.3 の素材破壊エンジン（WebGL2、8素材、断面、音響）と v0.4 の `combat/world.js`・`combat/formations.js`（群れの形、多層ボス）を再利用 | 既存の資産を使い切る。共有ファイルは変更していない（FEEL 側で設定を上書き） | 採用 |
| 入力は「指の場所と向き」を正にし、キャラクターの移動は自動 | v0.4 の不一致の原因（§2）を根本から消す | 採用 |
| 自動プレイヤーも、人間と同じ入力の経路（`P.down / move / up`）を通して操作する | 入力の判定（52px で斬る、0.24秒で長押し など）まで含めて検証するため | 採用 |
| 「人間らしい」プレイヤー（群れの濃い所を見て、そこを触る）を v0.4 と v0.5 の両方に同じ規則で走らせる | 操作の前後比較を、同じ物差しで行うため | 採用 |
| 強化の効果は、通しプレイとは別に「同じ群れに一手だけ」のベンチで測る | 通しプレイでは群れの量が上限になり、強化の差が見えにくい（§3 の失敗） | 採用 |

## 2. 操作の再設計と前後比較
### v0.4 のずれの原因
v0.4 は、なぞった形のまま**キャラクターの位置から**動く相対操作だった。人は敵の上をなぞる・タップするので、攻撃は見ていた場所と別の所で起きる。魔法使いは入力の 60% がマナ不足で無効だった。

### 前後比較（同じ「人間らしい」プレイヤー、4シード）
| キャラ | 狙った敵に当たった | 0.6秒以内に何も壊れなかった入力 | 無視された入力 | 一入力あたりの撃破 |
|---|---:|---:|---:|---:|
| 大剣士 | 13% → **100%** | 59% → 5% | 0% → 0% | 0.62 → **12.05** |
| 拳闘士 | 3% → **100%** | 79% → 3% | 0% → 0% | 0.59 → **9.79** |
| 魔法使い | 24% → **100%** | 40% → 10% | 60% → **0%** | 1.69 → **13.12** |

「当たった」＝狙った敵が 0.6秒以内に壊れた／ひびが入った／潰れた／殴り飛ばされた。

### 実際のポインター入力（Chrome、スマホの画面サイズ、実時間。`tests/feel/input.mjs`）
| キャラ | 触った場所と攻撃の場所の距離 | 発動 | 発動→最初の破壊・命中 |
|---|---:|---|---:|
| 大剣士 | 20px（帯の中心） | スワイプの途中、52px 動いた時点（指を離す前） | 3ms |
| 拳闘士 | 1px | 指が触れた瞬間（0ms） | 65ms（踏み込みの時間） |
| 魔法使い | 3px | 指が触れた瞬間（1ms） | 11ms |

ほかに確認したこと（すべて合格）：拳闘士の5連打が取りこぼしなく5発になりコンボが続く、魔法使いのなぞりで魔法が3つ連なる、3キャラとも長押し→離すで大技が出る、強化の画面で時間が止まり、選んだ強化が反映される、コンソールエラーなし。

### 最初の攻撃までの時間
- 試合開始から最初の撃破まで：人間らしいプレイヤーで 0.4〜0.5秒（群れは最初から画面中央にいる）。
- 入力から最初の破壊まで（模擬の中央値）：大剣士 36ms、拳闘士 44ms、魔法使い 17ms（§4 の 72試合）。

## 3. 失敗と、その直し方（記録）
| 失敗・問題 | 原因 | 対処 |
|---|---|---|
| 1回目の強化が、開始から1〜2手で来る | 強化の条件を撃破数（30体）にしたが、v0.5 は一手で30体近く壊せる | 強化は時刻で来る（12秒、24秒）。強化前の時間を体感できる長さにした |
| ボスが2〜11秒で倒れる | 範囲攻撃が強くなり、v0.4 の硬さでは足りない | 叩く回数を 外殻6／中層4／核16 に。拳闘士は一点を叩くので、1発で3回分 |
| 撃破数が全キャラほぼ同じ（626体） | 敵の供給が上限。全部倒し切っている | 群れを常に画面にいるように出し、強化のたびに厚くする |
| 斬撃の軌跡がギザギザ | 線分ごとの「ひし形」の描き方 | 三日月の光（太い柔らかい光＋明るい縁）を、刃の進行に合わせて0.1秒で描く |
| ブラウザーのパネルで遊ぶと画面が止まる | パネルが非表示だと描画（requestAnimationFrame）が止まる。ゲームの不具合ではない | 実時間の検証は Playwright の Chrome で行った |
| 魔法使いが強化前から一回で群れの83%を壊す（成長の余地がない） | 魔法で飛んだ破片が、さらに周りを壊す連鎖が強すぎた | 強化前の魔法は破片の連鎖なし・雷は1段。強化で広がる |
| 大剣士の「衝撃波」が効かない（+0%） | 刃の先へ走る形だったので、群れの外で起きていた | 刃の線から両側へ広がる形に変更（41% → 83%） |
| 拳闘士の「ぶっ飛ばし」が弱い（+0.7体） | 遠くへ飛ぶだけで、群れの外へすぐ抜けていた | 殴った瞬間に周りの敵をビリヤードのように弾き飛ばす（4.0 → 11.7体） |
| 注釈を入れたら、雷の処理が消えた | 一行のコードの途中に `//` を入れて、後ろを全部コメントにした | ブロックコメントに直した（ベンチで例外を検出） |
| 強化なしの対照が、最初から厚い群れと戦っていた | 群れの厚さを「選んだ強化の数」で決めていた。対照は強化を2つ持った扱いだった | 群れの厚さは時刻（12秒、24秒）で決める |
| ボスが出ない（例外） | 群れが厚くなり、体の数の上限（260）に達していた | ボスの出現前に古い破片から片づける。FEEL では上限を230にした |
| ボスだけの試験で、時間切れを「撃破」と数えていた | 時間切れでもボスは崩れる（罰なし）ので、崩れたかどうかで判定していた | 撃破したかどうかで判定 |

## 4. 成長の検証
### 強化前後の破壊規模（同じ群れに一手、24試行。`tests/feel/bench.mjs`）
| キャラ | 強化なし | 強化1つ（最大） | 強化2つ（最大） |
|---|---:|---:|---:|
| 大剣士（人間らしい） | 9.7体（群れの41%） | 衝撃波 19.3体（83%） | 二重＋衝撃波 22.2体（95%） |
| 拳闘士（人間らしい） | 4.0体（18%） | ぶっ飛ばし 11.7体（47%） | ラッシュ＋追加破砕 11.5体（47%） |
| 魔法使い（人間らしい） | 16.8体（71%） | 大魔法陣 21.5体（90%） | 大魔法陣＋連鎖拡大 23.3体（100%） |

強化はどれも、見た目と壊れ方が変わる（刃が金色で太くなる／二本目の刃／両側へ広がる波／弾き飛ばし／衝突ごとの輪／4段の雷／二度目の爆発）。画面：`sheet_growth.png`。

### 通しプレイでの成長（6シード、人間らしいプレイヤー。`tests/feel/sim.mjs`）
| キャラ | 一手あたり 強化前 → 強化後 | 一手の最大 強化前 → 強化後 | 対照（強化なし）の一手あたり |
|---|---|---|---:|
| 大剣士 | 11.1 → 23.5 | 22 → 55 | 8.4 |
| 拳闘士 | 9.1 → 18.5 | 33 → 62 | 7.8 |
| 魔法使い | 11.9 → 36.2 | 33 → 57 | 8.4 |

強化後の数字には「群れが厚くなった」効果も含む。強化そのものの効果は、ベンチと対照（試合全体の一手あたり：強化あり 13.6／9.8／14.0、強化なし 8.4／7.8／8.4）で見る。

### ボスの撃破時間（ボスが出てから核が崩れるまで）
| キャラ | でたらめ | 人間らしい | 上手い | 人間らしい・強化なし |
|---|---|---|---|---|
| 大剣士 | 15.1秒（6/6） | 6.0秒（6/6） | 5.1秒（6/6） | 倒せない（0/6、時間切れで崩れる） |
| 拳闘士 | 15.3秒（6/6） | 10.6秒（6/6） | 8.0秒（6/6） | 17.4秒（6/6） |
| 魔法使い | 19.9秒（1/6） | 9.9秒（6/6） | 8.7秒（6/6） | 倒せない（0/6） |

試合全体は、人間らしいプレイヤーで約46〜51秒、でたらめで55〜60秒で終わる。

## 5. 60秒のあとに再挑戦したくなる仕掛け（実装したもの）
- 結果画面に「一手の最大 強化前 → 強化後」と「一手あたり」を並べ、強くなったことを数字で見せる。
- 前回との差（+N 撃破）。自己ベスト（撃破、一手の最大、ボス撃破時間）を更新すると NEW。
- 強化コレクション（キャラごとに 3 つのうち何を試したか）。まだ試していない強化を名前で薦める。
- 大きな「もう一回」、同じ戦場でキャラを変える（比較表つき）、別の戦場。
- 記録は端末のブラウザーにだけ保存する（保存できない環境でもゲームは動く）。

## 6. 人間の評価が必要な項目（未検証）
| 項目 | AI で分かったこと | 未検証の部分 |
|---|---|---|
| 意図と結果の一致 | 狙った敵に 100% 当たる。指の場所から 1〜20px | 指でのスワイプが「思った向き・場所」に感じられるか |
| 入力の即応性 | 発動→破壊 3〜65ms | 拳闘士の踏み込み（65ms）が遅く感じないか |
| バッサバッサ／ボンボン／一斉に壊れる | 一手あたり 10〜14体 | **気持ちよいかどうか**（ここは人間にしか分からない） |
| 強化で明らかに強くなったか | 破壊規模が 1.4〜2.9倍 | 体感として「さっきより強い」と感じるか。2択で迷えるか |
| ボスの手応え | 強化ありで 5〜11秒 | 大剣士（6秒）は早すぎないか |
| 再挑戦したくなるか | 仕掛けは実装した | 実際に「もう一回」を押すか |
| 音 | — | 大量破壊の音が気持ちよいか、疲れないか |
| Android 実機の性能 | PC で CPU 4倍スロットル時、p95 9.8〜11ms（60fps の予算 16.7ms 以内） | 実機での描画速度と発熱 |

## 7. 性能
PC の Chrome、CPU 4倍スロットル（中位の Android の近似）、上手いボットが14秒、描画あり：
フレーム p95 は 大剣士 9.8ms／拳闘士 11ms／魔法使い 10.5ms（描画 p95 は 6.9〜7.6ms）。v0.4（7.5〜9.2ms）より重いのは、群れが厚いため。60fps の予算（16.7ms）には収まるが、v0.3 の目標（8ms）は超えている。
FEEL だけ体の上限を 260 → 230 にした。

## 8. 総監督の所見と次の仮説
- 「触った所が壊れる」に変えたことで、操作のずれは数字の上では消えた。あとは指の感触（人間の評価）。
- 3キャラの性格は保てている：大剣士＝一振りで面を斬る、拳闘士＝殴って飛ばして玉突き（連鎖撃破が一番多い）、魔法使い＝一点から一斉に弾ける。
- 大剣士の「衝撃波」、拳闘士の「ぶっ飛ばし」、魔法使いの「大魔法陣」が数字では強い。強化の選択が一択にならないかは、人間の試遊で確認する。
- 次の候補：強化の種類を増やす前に、人間の評価で「強くなった感」が弱い強化を作り直す。キャラの絵の生成。Android 実機での計測。
