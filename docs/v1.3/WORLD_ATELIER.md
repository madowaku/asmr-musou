# ASMR MUSOU v1.3 WORLD ATELIER

`studio.html` を Chrome で開くと試遊できます。起点は `feat/v1.2-tactile-growth` の `adf7dd3`。双剣士、ボス、ゼリー切断、75秒の出現隊形を含むローカル変更13件を、独立ブランチの `dd917f6` に取り込みました。

## 美術と描画

720×1280 を共通座標とし、部屋の構造や物語は上部と周辺に配置しました。キャラクターの装飾とつながる金色の四つ花、丸い縁、淡い反射光を8ステージに通しています。床は一体で、中央の色差を抑えています。背景と戦闘の投影には既存の WebGL 描画を共有し、防衛ラインは既存ルールの `K.LINE` に描画します。

跡は既存の素材破壊通知から描画用の座標を受け取り、新しい順に最大56個を保持します。全8素材を1枚の小さなテクスチャにまとめています。結果画面の「破壊の跡を見る」で操作を止めた床面を表示します。図鑑の背景選択は通常のフリープレイと撮影モードで共通です。「無地」では背景アート、環境演出、床の破壊跡を隠します。画面の動きが無効の場合と OS の視差効果軽減設定では、環境演出を静止表示します。

## 画像の出所と再出力

2026年11月28日、Codex の組み込み ImageGen でこの版向けに8枚を生成。Stage 1〜3 は既存の `studio/art/slasher-portrait.webp` と `spinner-portrait.webp` を色・質感の参照に使いました。残り5枚は Stage 1・3 の生成画像を構図と装飾の参照にしています。生成画像には人物、敵、UI、文字を含めていません。

仕上げ時に、v0.9 の依頼に添付されていた5人の全身設定画と、SOAP PARTY の理想画を実画面と見比べました。理想画の泡や断面に見られる水色・紫・ピンクの反射を、環境の泡と床の跡に反映しました。

共通の生成指示は、縦長9:16、斜め上から見た明るい玩具調の幻想空間、画面中央の幅70%と高さ26〜87%を薄い色の空いた床にすること。輪郭の強い造形は施設と一体にして周辺へ配置しました。原画は Codex の `generated_images/01a22008-0951-7520-afa8-e927f5d6840d` 内にあります。

FFmpeg の Lanczos で盤面を 720×1280 に縮小し、libwebp の品質83で保存。サムネイルは原画の上端から `crop=iw:iw*0.57:0:0` で切り出し、360×205、品質84で保存しました。

```sh
ffmpeg -i source.png -vf scale=720:1280:flags=lanczos -c:v libwebp -quality 83 plate.webp
ffmpeg -i source.png -vf 'crop=iw:iw*0.57:0:0,scale=360:205:flags=lanczos' -c:v libwebp -quality 84 material-thumb.webp
```

`studio/art/worlds/` の素材ごとの `.js` は、WebP を Base64 化し `document.currentScript.plateSource = 'data:image/webp;base64,…';` に載せたローカルアセットです。ローカル HTML からも WebGL に転送できます。選んだ盤面だけを開始後に非同期で読み込み、先に簡易床を描画します。サムネイル8枚の合計は約150 kB。背景 WebP は8枚で約618 kB、プレイ時に取得する1ステージ分のスクリプトは約88〜120 kBです。環境演出と床の跡は `studio/world-atelier.js` で生成します。

## 検証の再実行

```powershell
$env:WORLD_BASELINE_HTML = 'C:\path\to\v1.2\studio.html'
node tests/studio/world-atelier.mjs C:\path\to\captures
```

全8ステージの通常・無双・ボス戦を 360×640 と 390×844 で保存します。無双とボスの撮影では時計と装備を設定し、既存の出現処理と攻撃判定を使います。自然進行の攻略は既存の `v10-verify.mjs` と `v12-growth-boss.mjs` で別途検証します。計測値はデスクトップ Chrome のモバイルエミュレーションです。描画間隔は requestAnimationFrame の間隔、入力の値は Chrome のタッチイベントから次の描画コールバックまでです。物理画面の表示完了や実機の発熱は含みません。

| 画面 | 通常時の描画間隔 p95 | 密集時の描画間隔 p95 | タッチから次の描画コールバック p95 |
| --- | ---: | ---: | ---: |
| 360×640 | 13.6 → 13.4 ms | 13.5 → 13.6 ms | 40.9 → 39.8 ms |
| 390×844 | 13.5 → 13.5 ms | 13.5 → 13.5 ms | 39.2 → 41.0 ms |

左が引き継ぎ元の v1.2、右が v1.3 です。描画間隔は各100点、タッチは各25点です。密集時は両方とも砂の敵32体、v1.3 は床の跡を上限の56個置きました。選択から背景の読み込み・デコード完了までのローカル測定は8ステージで約10〜31 msでした。

`npm test`、`npm run test:lab`、FLOW のスモーク、Studio の `formations`、`play`、`iai`、`synergy-film`、`v10-verify`、`v12-growth-boss` が通過しました。旧 `roller-feel` は通常起動時の `LAB.combat.rollerFeel` を未定義と想定しており、v1.2 と v1.3 の両方で同じ箇所が失敗します。現行の8素材×5人の回帰テストには ROLLER も含まれます。
