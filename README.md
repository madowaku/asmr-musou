# ASMR無双 / ASMR MUSOU v0.2 tactile

45秒、玩具の殻を割り、泡をつなぎ、芯をむぎゅっと潰すブラウザゲーム。

## 起動と操作

1. `index.html` を Chrome で直接開く（ダブルクリック / `file://`）。サーバー不要。
2. 「さわってスタート」で開始。音源48個をこの最初の操作時に生成する。
3. タップで素材を割る。なぞると1ストロークにつき各敵1回、C D E G A…の上昇音。3体以上なら小さなフィニッシャー。
4. 約0.55秒の長押しでむぎゅっ。押す途中は変形・圧力リング・音が育つ。0.18秒以上押して途中で離すと無傷で戻る。
5. `🔊` は**音と振動**をまとめて切り替える。小さな音量から試すこと。振動は対応ブラウザ・端末のみ。

マウス・タッチ・ペンの Pointer Events を利用し、同時2ポインターまで対応。フォーカス喪失・キャンセル時は長押しを解除。タブ復帰では非表示時間を飛ばす。横画面の小さい端末には縦向き案内を表示する。

## 素材と45秒の流れ

- ロウ：3タップ。ツヤのある丸い殻 → 細いヒビ → 殻が落ちてマットなピンクの芯 → 破裂。長押しなら一度で潰せる。
- プチプチ：1タップで破裂。155px以内でつながる泡を40–70ms刻みで連鎖させる。
- ゼリー：低いしずく形。最初のタップでバネ振動とむにゅ音、次のタップか長押しで潰れる。
- 氷：角ばった結晶。1タップで白い亀裂、2タップで破片と響き。
- 小敵は最大8 / 10 / 12体。開始時に中央のロウと3体の泡を配置し、追加は下端または左右から漂う。HUD手前でフェードアウトし、ワープしない。
- 32秒でボス。残る小敵を得点つきの連続ポップで消し、追加出現を停止。中央 `y=560` で殻3層（各3ヒット）→ 芯（4タップまたは長押し1回）→ 大きな解放。殻への長押しは1ヒット。
- 撃破後は軽いボーナス敵。45秒で結果へ進む。ボス未撃破の減点はない。

破断は `fracture()` に集約。状態・破片・音源開始・波紋・振動を同時に切り替える。通常40ms / 撃破70ms / ボス層180msのヒットストップ（重複は最大値）、最終破裂450msのスローモーション。入力・描画・タイマーは止めない。小さな拡大と揺れのみで、赤フラッシュなし。

## 音とアート

**すべての音は `synth_*` の手続き合成で、実録ASMRではない。音の品質・快適さ・素材らしさは人間による耳チェックが必要。**

`audio.js` は seeded RNG と Float32Array DSP で16種×3 variationを事前生成する。粒状クラック、ノイズ励起共振器、フォームントの湿った音、非整数倍の氷の響き、C–E–G–Bの最終和音を組み合わせる。破断時は `AudioBufferSourceNode.start(AC.currentTime)` で再生し、±3%のピッチ揺らぎを加える。音量正規化後、1音名4声 / 全体16声まで（古い声を置換）。声ごとのGain → Compressor（−18dB、4:1）→ HighShelf（9kHz、−3dB）→ Master Gain。OFFでは再生中の声も止める。

絵は引き続き Canvas 2D の手続き描画。`assets/` の並行制作物はまだ読み込まない。後続のアート統合は `window.ASMR.SPRITES[type][stage]` にロード済み Image を入れれば差し替えられる。未登録・未ロードなら手続き描画へ戻る。ボスのキーは `shell_0_0`〜`shell_2_2` / `core_0`〜`core_3`。破片・バネ変形・圧力リングは共通。

古典的な `<script defer>` と `window.ASMR` を使い、ES modules、fetch、XHR、CDN、外部ライブラリはゲームに不要。パーティクル上限600。背景・グラデーションを再利用し、多数オブジェクトの `shadowBlur` は使用しない。

## 検証と試聴ファイル

Node.js とローカルの Google Chrome が必要。開発用依存は `package.json` の Playwright 1.56.1（ゲーム実行には不要）。この作業環境にはインストール済み。別環境では `npm install` で用意する。

```sh
npm run check
npm test
node tools/render-sfx.cjs
```

- `npm test` は Node + Playwright、`chromium.launch({ channel: 'chrome', headless: true })`、通信を無効にした `file://` で実行。Python版 `tests/smoke.py` は `tests/smoke.mjs` に置き換えた。
- メニュー、音声の初期化、素材段階、泡の連鎖間隔、実マウスのスワイプ・長押し・早離し、ボスの全段階、ミュート、声数上限、45秒終了・再挑戦を確認。360×640 / 412×915 は mobile + hasTouch の `touchscreen.tap` と回転を確認。console/page errorと外部通信は0件を要求。
- `screenshots/` に title / play / swipe / hold / boss_act1 / boss_core / boss_final / result、追加のwax_core・モバイル画像を保存。
- `assets_audio_preview/synth_<name>_<1..3>.wav` に48kHz・16bit・monoの全48音を書き出す。ゲームはこのWAVを読み込まず、同じDSPをブラウザで実行する。
- ピーク、RMS、Hann窓FFTの振幅加重スペクトル重心を表として出力し、`assets_audio_preview/analysis.md` に保存。−1dBFS超・無音・非有限値なら失敗。測定は個別バッファ、量子化前・ミックスバス前。
- テスト用 `window.__asmrTest` に getState（stage/act含む）、hitAt、spawn、skipTo、end、audioStats 等。`?seed=1` で素材配置と音の変化を再現可能。長押し・タッチは実入力で検証。

## 残る確認

自動テストは人間の試遊・耳チェックを代用しない。Android実機の60fps、熱、入力遅延、振動、スピーカー／イヤホンでの音量・快適さは未検証。初回のDSP生成時間も実機で確認が必要。音源単体のピーク検査は全ミックスの音圧・聴感を保証しない。アート統合・公開はこのタスクに含まない。

`ORCHESTRATOR_BRIEF.md` 冒頭の「v0.1」「Python smoke」「リアルタイム仮音」は出発点の記述。このv0.2では本READMEのNodeテスト・事前生成DSPを採用している。ゼリーは今回の具体的な操作仕様（1回目で揺れ、次のタップで潰す）に従っている。

素材の生成方法と出所は [ASSETS.md](ASSETS.md)、全体の方針は [ORCHESTRATOR_BRIEF.md](ORCHESTRATOR_BRIEF.md) を参照。
